# 后端接口与数据约定

## 访问方式

开发时 React 经 Vite `/api` 代理访问 `127.0.0.1:8080`。业务接口使用 POST JSON，路由名统一为消息类型名去掉末尾 `Message` 再转小写，例：`SendMessageMessage → sendmessage`。稳定注册元数据不依赖前端压缩后的 constructor.name，后端测试校验两端的公共注册名称。

`StartSessionMessage` 为初始化访客身份的特殊路由，需要设置 Cookie，前端有对应 identity 调用文件。`GET /api/health` 为进程健康端点，不作为业务消息；当前返回进程已启动状态，不是持续数据库可用性的保证。

| 消息 / 路径 | 输入 | 返回 |
| --- | --- | --- |
| StartSessionMessage / startsession | `{}`，可带已有 Cookie | `{mode:"server-demo"}`，Set-Cookie |
| GetStateMessage / getstate | `{}` | SavedState |
| CreateConversationMessage / createconversation | id（UUID） | Conversation；相同本人 ID 可重试 |
| SendMessageMessage / sendmessage | conversationId、requestId（UUID）、content | 最新 Conversation |
| ListConversationsMessage / listconversations | `{}` | 本人会话数组 |
| GetConversationMessage / getconversation | id（UUID） | 本人 Conversation |
| DeleteConversationMessage / deleteconversation | id（UUID） | `{ok:true}` |
| SetFavouriteMessage / setfavourite | id（已知卡片）、saved（布尔） | `{ok:true}`；设置目标状态而非服务端翻转 |
| AddMoodMessage / addmood | id（UUID）、feeling、note | 服务器时间的 Mood，同 ID 同内容可重试 |
| DeleteMoodMessage / deletemood | id（UUID） | `{ok:true}` |
| UpdatePreferencesMessage / updatepreferences | preferences | 已保存 Preferences，并更新 Cookie 保持方式 |
| ClearDataMessage / cleardata | `{}` | `{ok:true}`，原子清空本人内容 |

除初始化和健康检查，其余接口必须有有效访客 Cookie。请求中的 ownerId/userId 不作为可信身份。未知或不属于本人的资源均返回 404，不公开他人会话是否存在。

## 类型

- Conversation：id、title、createdAt、updatedAt、messages、direction（可空）、revision。
- Message：服务器 id、role（user/assistant）、content、createdAt。
- Mood：id、feeling、note、createdAt。
- Preferences：nickname、remember、reducedMotion。
- SavedState：version=1、conversations、favourites、moods、preferences。前端快照不持有令牌。
- direction：study、relationships、self、loneliness、change；不确定时为空，早期不分类。后端阈值通过 QIYU_MINIMUM_TURNS 配置。

## 表与事务

| 表 | 归属 | 保存内容 |
| --- | --- | --- |
| visitor_sessions | identity | 访客 ID、令牌 SHA-256 散列、固定到期时间 |
| preferences | identity | 昵称、保持身份及减少动态偏好 |
| conversations | conversations | 独立所有者列、JSONB 会话、revision 与排序时间 |
| reply_requests | conversations | 所有者、请求编号、会话关联及原输入；不重复缓存全量历史 |
| moods | journal | 独立所有者列、JSONB 手记 |
| favourites | collection | 所有者及卡片 ID 的唯一组合 |

同一访客写事务取得该访客行锁；读取整份快照也在该锁下完成，保证多表一致。会话保存另检查 revision。当前本地模板在单事务内完成消息和幂等关联提交；失败或取消全部回滚。

重复请求必须保持相同 conversationId、requestId 和正文，不能通过重试改变内容。重放返回当前服务器会话（可能包含后续轮次），不再次追加消息。删除会话时关联请求级联删除，旧 Send 不能凭原请求编号恢复已删除会话。前端遇到删除重试的 404 会重新读取服务器快照作为已删除状态。

## 限额和错误

- 每条输入 1—2000 字符，按 UTF-16 长度计；每段最多 250 轮。
- 每个访客最多 100 段会话、500 篇手记；手记备注最多 1000 字符，昵称最多 20 字符。
- HTTP 请求体上限 32 KiB；超出返回 413。
- 错误体：`{code, message}`，不返回 SQL、连接配置、堆栈或倾诉正文。
- 400：字段或业务输入不合法；401：身份缺失或过期；403：来源拒绝；404：不可访问；409：幂等或版本冲突；413：请求过大；500：服务失败。
- 前端请求超时为 15 秒；失败可使用原请求编号重试，或重新载入服务器已保存内容。重新载入不会保留尚未确认的乐观消息。

## 当前边界

访客会话不等于正式账号。Cookie 不能用于跨设备找回；默认会话 Cookie，开启保持后最长七天，服务器身份固定七天失效。当前仅监听本机，Cookie 未开启 Secure，不能直接作为公网 HTTPS 部署配置使用。

本版不迁移旧浏览器数据，不提供后台浏览所有用户倾诉的管理员页面，不将任何数据库或真实对话提交到 Git。未来外部模型须释放数据库连接后调用，再以版本和请求状态提交结果。
