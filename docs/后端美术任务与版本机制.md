# 后端美术任务与素材版本机制

日期：2026-10-31。对应[游戏生成与美术保留规则](./游戏生成与美术保留规则.md)。

## 已落实的行为

1. 新游戏制作会根据已确认的类型、世界观和人物建立素材槽位及独立任务；任务携带本次设定、参考图ID和方案版本。卡牌增加卡面，MOBA/塔防增加防御塔等所需对象。
2. 美术清单独立保存于 `workshop_artwork`，不放在会被草稿编辑清除的当前游戏配置里。修改数值、规则、名称后，重新制作直接复用原素材ID、版本和哈希；只为新增或缺失的槽位补建任务。
3. 局部改图必须明确提供目标槽位和修改说明。任务携带旧素材版本，执行器将原图交给图片编辑服务；不使用无原图的全新生成代替局部编辑。未指定的素材不重画，新图完成前保留当前可用图。
4. 生成原图与加工成品分别存储，记录SHA-256、父版本、生成来源及加工关系。处理器验证PNG/JPEG、体积和尺寸，按用途适配尺寸并保持原始比例与透明通道，不覆盖原始字节。
5. 失败、阻塞、执行中、成功、过期分别记录。重试只恢复指定失败/阻塞任务，成功任务不重新执行。120秒执行租约和执行标识阻止旧结果覆盖新结果；模型及加工步骤90秒超时，取消请求会记录失败，重启后过期任务可显式重试。
6. 只有所需素材全部就绪且没有待处理视觉修改，才绑定到新原型配置。配置连同具体素材版本存入 `workshop_game_versions`；可查询最近100个配置快照，也可恢复某张素材的历史版本。
7. 所有操作校验作品归属。完成任务的写入只提供给后端内部计划，客户端不能把上传参考图直接登记成系统生成图。

## 事务与执行边界

公开API仍使用独立消息和 `plan(connection): IO[Response]`。普通消息在短事务中执行。制作和处理美术任务使用分阶段端点：

```text
鉴权 → 短事务保存或领取任务 → 提交并释放连接
     → 图片服务调用 → 校验与加工图片
     → 新短事务核对任务执行标识和旧素材版本 → 保存原图、成品与版本
```

外部模型与Java图像处理位于 `services/system/artwork` 基础设施边界，通过显式注入的 `ArtworkProvider` 组合IO。领域状态转换位于所属服务私有的纯函数中；跨模块通过公开消息或Table方法调用。没有进程全局的可变业务存储，也没有请求结束后无人管理的后台生成任务。

## 接口变更

仍使用 `POST /api/<消息名称去掉Message并转小写>` 和Bearer访客令牌。

`GenerateGameMessage` 返回值已从直接返回Project改为：

```json
{
  "status": "waiting_for_provider",
  "project": { "...": "Project" },
  "artwork": { "...": "ArtworkManifest" },
  "message": "所需美术尚未完成，当前不是完整游戏。"
}
```

| status | 含义 |
| --- | --- |
| waiting_for_provider | 素材未完成且图片服务未配置；不能显示制作成功 |
| artwork_pending | 有待执行美术；配置了图片服务的实际端点会在提交任务后执行，再返回最终状态 |
| artwork_failed | 存在失败任务，保留已成功素材，等待显式重试 |
| prototype_ready | 美术已绑定到规则原型配置；还需要前端加载和可玩验收，不代表全部产品完成 |

每个素材绑定包含槽位、素材版本、原图ID、成品ID以及两个内容哈希。已存在的旧规则原型可读取，缺失的 `artworkBindings` 解码为空列表；它们不能绕过新的美术完成门槛再次交付。

新增接口：

| 消息 | 输入 | 返回/用途 |
| --- | --- | --- |
| GetArtworkRequirementsMessage | `{projectId, expectedVersion}` | 已确认方案对应的美术需求；不是图片产物 |
| PrepareArtworkMessage | `{projectId, expectedVersion}` | 同步槽位和任务；已完成素材默认复用 |
| GetArtworkManifestMessage | `{projectId}` | 当前素材绑定、任务和历史记录 |
| RequestArtworkEditMessage | `{projectId, expectedVersion, expectedManifestRevision, requestId, slotIds, instruction}` | 显式局部视觉修改，重复请求标识幂等 |
| ProcessArtworkTaskMessage | `{projectId, taskId}` | 领取并分阶段处理一个任务；未配置服务时返回blocked |
| RetryArtworkTaskMessage | `{projectId, taskId}` | 只重置指定失败/阻塞或租约过期任务；成功任务不重画 |
| RestoreArtworkRevisionMessage | `{projectId, expectedVersion, expectedManifestRevision, revisionId}` | 恢复某项素材的旧版本，不删除历史；再制作可绑定该版本 |
| ListGameVersionsMessage | `{projectId}` | 最近100个原型配置快照，含当时绑定的素材版本 |

`expectedVersion` 是作品规则/方案版本，`expectedManifestRevision` 是美术清单版本，两者独立。SaveProjectMessage只改草稿；修改原始资料仍需重新整理、确认游戏方案，但不会清空独立美术清单。视觉更新应由前端把用户明确要求转换成目标槽位和 `RequestArtworkEditMessage`，后端不猜测任意文字是否表示要求重画全部美术。

## 目前没有实现的部分

- 真实图片模型提供方尚未选择和接入。生产入口使用 `UnconfiguredArtworkProvider`，明确返回等待配置或阻塞。不会用开发示例图、参考图或合成测试图片假装按用户设定生成成功。
- 测试中注入的图片服务只创建合成PNG，用于验证流程、加工和保存；不能证明真实模型的画面质量、人物一致性或局部编辑效果。
- 当前加工包括格式校验、等比尺寸适配、透明通道保留和PNG导出；智能抠图、动画生成、自动切帧及完整纹理流水线尚未实现。
- 前端需适配新的制作状态和素材绑定。已有前端开发稿未在本轮修改，也未随本轮提交。图形运行器实际加载和最终可玩性未在本轮验收。
- 支持读取原型快照与恢复单项美术；完整游戏规则的一键回滚、生产调度、存储配额和真实模型调用预算尚未实现。

这些边界不降低最终产品要求，只说明当前后端已实现和仍待接入的范围。
