# 前端实现与验证记录

日期：2026-10-31。

## 交付范围

新增 React + TypeScript + Tailwind 前端：创作工作台、作品列表、制作与美术管理、图形原型试玩。前端消息调用与现有 Scala 3 后端对应，制作接口按 GameBuildResult 的真实状态处理。

新游戏所需素材缺失时不能进入可玩完成态；图片服务未配置时展示等待说明并保留任务。素材浏览支持原图、加工图、用途、哈希、历史及局部恢复。视觉修改必须选定已有素材并填写说明，其余素材保持原版本。规则和世界观修改通过工作台提交，不自动整套重画。

试玩读取具体游戏快照的素材绑定，检查必需槽位、实际内容 SHA-256 与图片解码，再装载对应卡牌、回合制战斗、塔防或单线对抗运行器。旧的无素材绑定原型不能绕过检查。

状态分工：页面 Hook 管理请求、文件读取、图片解码与定时器等边界；资料校验、素材状态汇总和游戏状态转换使用纯函数和不可变值；未引入隐式共享可变业务状态或无必要的 Zustand Store。

## 浏览器联调

正式后端（8080）与前端（5173）：

1. 缺少参考玩法时阻止整理方案并显示提示。
2. 填写塔防类型、参考模式、世界背景、角色姓名/性格/口头禅/技能，刷新后恢复未保存草稿。
3. 整理、确认并提交制作后进入制作页；展示 0/4 素材与等待图片服务，未开放试玩入口。
4. 单项处理在服务未配置时保留该任务并显示可重试，其余任务不受影响。
5. 测试服务器停止后恢复正式后端，重新读取同一作品资料成功。

验收专用后端（8081）与前端（5174）：

1. 仅测试类路径和 WORKSHOP_UI_TEST=1 可启用合成图片服务。测试素材不是实际生成美术。
2. 卡牌作品完成六项素材的生成、加工、真实下载和绑定，组装快照。
3. 仅选择场景进行夜景修改，场景历史和内容哈希发生变化；另外五项素材历史仍为一版，未触发重新生成。
4. 将场景恢复至初始版本后，其加工哈希恢复为初始值，历史继续保留；重新组装后可进入试玩。
5. 试玩先核验并加载六项图片，页面明确标记测试合成素材；出牌、格挡、结束回合后，血量、敌方血量和回合数按规则改变。
6. 390×844 窄屏检查：导航与内容按响应式布局显示，试玩无横向溢出。检查后已恢复默认窗口尺寸。
7. 专用测试服务器和测试前端已停止；保留正式预览。
