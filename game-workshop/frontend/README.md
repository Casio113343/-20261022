# 造游工坊前端

React 19 + TypeScript + Vite + Tailwind。连接现有 Scala 3 后端，包含创作工作台、作品列表、制作与美术管理、图形原型试玩四个页面。

## 启动

先按 [后端说明](../backend/README.md) 启动 PostgreSQL 与正式后端，然后在本目录执行：

```powershell
npm ci
npm run dev
```

访问 http://127.0.0.1:5173 。Vite 默认将 `/api`、`/health` 转发到 `127.0.0.1:8080`。浏览器访客令牌保存在 localStorage，作品保存在 PostgreSQL；清除令牌将失去当前访客的作品访问凭据。

```powershell
npm run build
npm test
```

## 已实现

- 分类与通俗介绍、参考游戏或模式必填、世界观和人物字段、PNG/JPEG 参考图片上传及用途说明。
- 浏览器草稿恢复、服务端保存、版本冲突提示、模板补充方案审阅与确认；旧本地草稿不会自动覆盖较新服务端资料。
- 制作状态与真实美术任务展示；图片服务未接入时保留请求并显示等待，不跳入空白试玩。
- 素材分类、原图和加工图、历史版本、指定素材修改、单项失败重试和旧图恢复。普通规则修改默认复用美术。
- 游戏快照列表；试玩前校验必需素材绑定，读取实际图片、核对 SHA-256 并等待解码，失败时关闭试玩并提供重试。
- 卡牌、RPG 回合战斗、塔防、单线对抗四种基础规则运行器使用绑定的场景、角色、卡面或塔图片。局内状态为 React 受控状态，刷新重新开局。

## 边界与限制

真实图片生成模型仍未接入，正式后端使用 UnconfiguredArtworkProvider；目前无法从自由描述交付完整的新游戏美术。上传参考图不等于生成。模板文字技能和方案补充不会自动编译为任意新机制；四种运行器是本地规则原型，不等于完整 MOBA/RPG 产品。没有联网对战和生产部署。

验收专用后端位于 `backend/src/test/scala/services/FrontendFixtureServer.scala`，只能通过测试类路径且显式设置 `WORKSHOP_UI_TEST=1` 启动，监听 8081，生成有明确标识的合成小图片，仅验证界面和素材链路。它不是正式图片服务。前端可临时设置 `WORKSHOP_API_TARGET=http://127.0.0.1:8081` 连接该测试服务；正式默认仍为 8080。

## 结构

`apis` 为与后端一一对应的消息调用函数，统一 `send` 负责路由、认证及错误；不额外增加仅转发的类，按编码规章 P_1-11 记录。页面内 `hooks` 管理显式副作用，`functions` 为纯业务计算，`components` 为局部视图。没有模块级可变业务状态。尚无需要 Zustand 的跨页面共享状态，未引入空 Store。

具体检查及未验证项见 [前端验证记录](../../docs/前端实现与验证记录.md)。
